## Overview

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) is an open protocol that standardizes how applications provide context to large language models (LLMs).
The ConfigCat MCP server lets you manage feature flags and configurations via the [Public Management API](/api/reference/configcat-public-management-api/) seamlessly from AI tools. 
It also enables your code editor to understand your feature flags, integrate the appropriate ConfigCat SDK into your project or even create new feature flags directly in your codebase.

## Features

- Manage organizations, members and permissions
- Create and update products, configs, and environments
- Manage feature flags and settings
- Manage tags and user segments
- Connect with integrations and webhooks
- Track activity with audit logs and zombie flag (stale flag) reports
- Find code references linked to your features
- Integrate ConfigCat SDK and implement feature flags in your project

## Connect to the MCP server

You can connect to the ConfigCat MCP server in two ways:

- [Remote MCP server](#remote-mcp-server): Connect to the hosted MCP server without installing or running anything locally. Authenticate with your ConfigCat account and use it from desktop or browser-based AI tools.
- [Local MCP server](#local-mcp-server): Runs on your machine as a process that your AI client starts. It connects to ConfigCat using your Public Management API credentials.

Both ways provide the same functionality.

## Remote MCP server

The remote MCP server uses Streamable HTTP and is hosted by ConfigCat, so you don't need to install or run anything locally.  
It uses **OAuth authentication**. Sign in to your ConfigCat account in your browser when prompted by the AI client.
The MCP server uses your ConfigCat user permissions. You can manage your MCP connections in the [ConfigCat Dashboard](https://app.configcat.com/).

:::info
To limit the MCP server's access, you can create a dedicated ConfigCat user with only the necessary permissions, such as read-only access,
and use that account to connect to the MCP server.
:::

## Local MCP server

You can also run the ConfigCat MCP server locally on your machine.

### Prerequisites

- [Node.js](https://nodejs.org/) version 16 or higher installed.
- [Public Management API basic auth credentials](https://app.configcat.com/my-account/public-api-credentials) created for ConfigCat MCP server access.

### Setup

Supply your [Public Management API basic auth credentials](https://app.configcat.com/my-account/public-api-credentials). 
The MCP server uses your Public Management API credentials and the associated permissions when performing actions.

The MCP server's configuration includes the following environment variables:

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `CONFIGCAT_API_USER` | Yes | – | Management API basic auth username. |
| `CONFIGCAT_API_PASS` | Yes | – | Management API basic auth password. |
| `CONFIGCAT_BASE_URL` | No | `https://api.configcat.com` | Override the API host (rarely needed). |

:::info
To limit the MCP server's permissions, you can create a dedicated ConfigCat user with only the necessary permissions,
such as read-only access, and use that user's API credentials.
:::

### Client Configuration

<Tabs>
<TabItem value="cursor-local" label="Cursor" default>
<Steps>
<Step>
Install [Cursor](https://cursor.com/).
</Step>
<Step>
Open **Cursor Settings** → **Tools & Integrations** → **MCP Tools** and select **Add Custom MCP**.
</Step>
<Step>
Add (or merge) this server definition into your JSON settings:

```json
{
  "mcpServers": {
    "ConfigCat": {
      "command": "npx",
      "args": ["-y", "@configcat/mcp-server"],
      "env": {
        "CONFIGCAT_API_USER": "YOUR_API_USER",
        "CONFIGCAT_API_PASS": "YOUR_API_PASSWORD"
      }
    }
  }
}
```
</Step>
<Step>
Save the settings. The MCP server starts on demand. You can now use it in Cursor's AI panel.
</Step>
</Steps>
</TabItem>

<TabItem value="claudecode-local" label="Claude Code">

<Step>

</Step>

</Steps>

## Interaction

After you install the ConfigCat MCP server in your AI client, you can prompt your agent to create or manage your feature flags and configurations.
Typically you need to click Run tool (or the equivalent option in your AI client) to execute the result.

For example, you could try asking

> Create a boolean feature flag called "my_awesome_feature" in the "Backend" config

or

> Turn the "my_awesome_feature" flag ON in all environments

or

> Update the "my_awesome_feature” flag in dev environment so it’s only enabled for users in Canada

or 

> Create a new feature flag by cloning the configuration of the "my_awesome_feature" flag, and name it "my_another_awesome_feature".

or

> Update the "my_awesome_feature" flag description: "When enabled, show my awesome feature.”

or

> List the stale feature flags that haven’t been modified in the past 6 days.

or 

> Show who last modified the "myNewAwesomeFeature" flag, and to what.

or

> Invite <span>sarah</span>@<span>example.com</span> to the "Main" product with "Administrators" permissions.
